# Тема 35 - Маркетплейс
Опорные числа брал на основе годового отчета маркетплейса ozon за 2025 год.
## Часть 1 - Базовые роли и сценарии
### Роли
1. Покупатель - основной пользователь, взаимодействующий с интерфейсом маркетплейса: просмотр карточек товаров, добавление в корзину, оформление заказов, сравнение товаров.
2. Продавец - создает карточки товаров, обновляет основную информацию (цена, фото, характеристики, описание), поддерживает остатки.
3. Сотрудник маркетплейса - модерация карточек товаров, ввод новых промо-акций.
### Сценарии
1. Заведение новой карточки товара в маркетплейсе продавцом.
2. Оформление заказа пользователем: проверка актуальной цены и наличия товара, резервирование товара, оформление доставки.
3. Поиск товара в каталоге пользователем: фильтрация товаров и просмотр карточек продавцов.
4. Заведение промо-акции сотрудниками маркетплейса: установка фильтров, логики срабатывания акции.
5. Обновление цен, остатков и информации о товарах продавцом.

Поиск товара - является главным и самым частотным сценарием в контексте маркетплейсов. Пользователи регулярно проверяют карточки по избранным категориям, скроллят ленты рекомендаций по товарам, а также осуществляют сравнительный анализ для отбора товаров. 

## Часть 2 - Допущения и основные статистики
### Допущения
1. **DAU** -  43.3 млн
	Средняя дневная аудитория сервиса - 43.3 млн. Показатель взят на основе годовой отчетности Ozon за декабрь.
2. **Число сессий на пользователя в день** - 2 
3. **Число поисковых запросов в сессии** - 10
	В среднем за сессию пользователь выполняет 10 запросов чтения: поиск, фильтрацию, загрузку списка товаров и открытие карточек. Для оценки принимается один внешний API-запрос на действие.
4. **Пиковый коэффициент нагрузки** - 3. 
### Нагрузка
#### RPS по просмотру и поиску
- 43.3 млн DAU -> 43.3 млн \* 2 = **86.6 млн** сессий в день
- 86.6 млн \* 10 = **866 млн** поисковых запросов в день
- В 1м дне - 86400 секунд: 
  866 млн / 86400 = **~10000 RPS**
- Учтем пиковый коэффициент:
  3 * 10000 = **~30000 RPS**

## Часть 4 - Нефункциональные требования
### Нагрузка
На основе расчета нагрузки обеспечить 43.3 млн DAU в день и пиковую нагрузку 30000 RPS по просмотру и поиску.
### Latency:
Обеспечить значения latency в соответсвии с приведенными ниже значениями.

Для каждого сценария примем допущения по целевым значениям задержки. Latency считаем как время от отправки API запроса до получения полного ответа.

| Операция                                                   | p50      | p95      | p99        |
| ---------------------------------------------------------- | -------- | -------- | ---------- |
| Создание черновика карточки товара                         | ≤ 200 мс | ≤ 500 мс | ≤ 1 000 мс |
| Создание заказа с проверкой цены и резервированием товаров | ≤ 300 мс | ≤ 800 мс | ≤ 1 500 мс |
| Поиск, фильтрация и сортировка товаров                     | ≤ 150 мс | ≤ 400 мс | ≤ 800 мс   |
| Получение карточки товара                                  | ≤ 100 мс | ≤ 250 мс | ≤ 500 мс   |
| Сохранение настроек промоакции                             | ≤ 200 мс | ≤ 500 мс | ≤ 1 000 мс |
| Обновление цены, остатка и информации о товаре             | ≤ 100 мс | ≤ 300 мс | ≤ 600 мс   |
Для частых действий - поиска и просмотра карточек - установлены более строгие ограничения, чтобы интерфейс быстро реагировал на запросы пользователя. Для оформления заказа допускается большая задержка, поскольку операция включает проверку цены, резервирование остатков и сохранение данных.

### Доступность
- Доступность пользовательского API должна составлять не менее **99,95% за календарный месяц** - доля валидных запросов должна завершаться без серверных ошибок и таймаутов.
### Сохранность данных
- При отказе одного сервера или одной зоны доступности подтверждённые заказы и платёжные записи не должны теряться: **RPO = 0**.
- Резервные копии создаются ежедневно и хранятся **30 дней**. Проверочное восстановление проводится **раз в месяц**.
### Согласованность данных
- Проверка и резервирование остатка выполняются атомарно: система не допускает резервирования количества товара, превышающего доступный остаток.
### Геораспределенность
- Сервис предназначен для пользователей на территории РФ
- Основные данные и резервные копии размещаются в РФ.
